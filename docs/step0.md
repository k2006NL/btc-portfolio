# Step 0: ノードとお友達になる

## UTXO とは何か
- 金庫を複数持って管理し、そこから出金とおつりを記録するのがトランザクション。そのたびに金庫を新品にしているイメージ
- UTXOすなわち未使用トランザクションアウトプットとは、新品金庫でまだ一回も支払いに使ってないもの

## coinbase 取引はなぜ 100 ブロック使えないのか
hello_rpc.py には以下のような処理が含まれる

```python
if info["blocks"] < 101:
        rpc("generatetoaddress", 101 - info["blocks"], miner)
```

これはコインベースの出力を使うなら100ブロック以上の承認が必要だからである。

それは何故か。
ブロックチェーンは枝分かれが起こることがある（フォーク）。
この時片方を無効にして整理し（リオーグ）、もう片方を伸ばすという処理が起こる。
普通の取り引きは、捨てられたブロックから待機室のようなものである mempool に戻り、新しいチェーンのブロックに入り直せる。
もしこの無効になったブロックにcoinbase取引が含まれていた場合、このブロックが掘られていないことになる。
coinbase取引は、ブロックを掘ったこと自体が報酬の根拠であるため、ブロックが消えると取引が復活できない
ゆえに、取引の安全のために100ブロック以上という制限がある。

## 練習で分かったこと
- 練習1: vin / vout を表として出力する
  - vin には金額がない
- 練習2: 手数料の計算
  - `getrawtransaction` で前の取引を持ってくる必要がある
    - vin は常に直前の取引を指すわけではない
    - あくまでチェーンとして繋がっているだけ
  - 同じ `vout` でも場所によって違う
    - tx["vin"][i]["vout"] と tx["vout"]
  - float の誤差対策で整数単位の satoshi に変換してから計算するとよい
  - vin が多い取引ほど手数料が大きい
